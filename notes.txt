Q. Difference between a Library and Framework?
A. Library is a collections of prewritten code snippets that can be used and reused to perform certain tasks. A particular JavaScript library code can be plugged into 
application code which leads to faster development and fewer vulnerabilities to have errors. eg react, jQuery
        Framework provides a basic foundation or structure for a website or an application. eg angular

        A key difference between the two is Inversion of control. When using a library, the control remains with the developer who tells the application when to call 
library functions. When using a framework, the control is reversed, which means that the framework tells the developer where code needs to be provided and calls it as 
it requires.

Q. Why is React known as React?
A. React is a JavaScript Library. The name ‘React’ was chosen because the library was designed to allow developers to react to changes in state and data within an 
application, and to update the user interface in a declarative and efficient manner.

Q. What is diference between React and ReactDOM
A. React: React is a javascript library, designed for building better user interfaces.
React-DOM: React-DOM is a complimentary library to React which glues React to the browser DOM
Whenever we use component, classes, elements, etc. We’re using React and whenever we use methods like render() or findDOMNode() we’re using React-DOM.
Earlier the ReactDOM was part of React package, but the split happened because React has nothing to do with browsers. That’s why we’re seeing tools and frameworks like
React-Native, React-Three being developed. These tools and frameworks don’t use React-DOM, but they do in fact use the idea behind React.

Q. What is difference between react.development.js and react.production.js files via CDN?
A. react.development.js -> 
    a. Ideal for development environments where debugging and code clarity are priorities.
    b. Unminified Code: Maintains readable code structure for easier debugging and understanding.
    c. Source Maps: Generates files that link back to the original source code, making debugging easier.
   react.production.js ->
    a. Optimized for real-world deployment, prioritizing performance and file size
    b. Minified Code: Significantly smaller file size by removing unnecessary whitespace and shortening variable names, leading to faster loading times.
    c. No Source Maps: Excludes source maps for reduced file size and potential security reasons.

Q. What is `Parcel/Webpack`? Why do we need it?

Q. What is Hot Module Replacement?
A. Hot Module Replacement updates only the modified module in the browser without performing a full page reload, preserving application state and improving development experience.

        - As you make changes to your code, Parcel automatically rebuilds the changed files and updates your app in the browser. By default, Parcel fully reloads the page, but in some 
          cases it may perform Hot Module Replacement (HMR). HMR improves the development experience by updating modules in the browser at runtime without needing a whole page refresh. 
          This means that application state can be retained as you change small things in your code.

        - HMR works by replacing the code for a module, and then re-evaluating it and along with all of its parents.
   2. Diagnostics

   3. Tree Shaking
        - It statically analyzes the imports and exports of each module, and removes everything that isn't used.
        - In production builds, Parcel concatenates modules into a single scope when possible, rather than wrapping each module in a separate function. This is called “scope hoisting”.
          Parcel’s implementation of scope hoisting works by analyzing each module independently and in parallel, and at the end concatenating them together. In order to make 
          concatenation into a single scope safe, the top-level variables of each module are renamed to ensure they are unique. In addition, imported variables are renamed to match the 
          exported variable names from the resolved module. Finally, any unused exports are removed.

Q. What is `.gitignore`? What should we add and not add into it?
A. .gitignore specifies files and directories that Git should not track or commit. We should add all the files in .gitignore that could be regenerated
   by other files like .parcel-cahce, dist, node_modules

Q. What is the difference between `package.json` and `package-lock.json`
A. (a) package.json 
   - maintains approximate version of the installed dependencies through ^/~ . 
   - maintains the installed devDependencies and dependencies. 
   - contains metadata and scripts

   (b) package-lock.json
   - maintains the exact version of installed dependencies
   - maintains the version of installed transitive dependencies

Q. Why should I not modify `package-lock.json`?
A. package-lock.json ensures consistent dependency versions across environments. Manual modification can lead to inconsistent installs and dependency resolution issues.

Q. What is `node_modules` ? Is it a good idea to push that on git?
A. node_modules folder is generated when we run 'npm install' because it contains the code of all the installed packages/dependencies. One should not push it to git because it consumes
   a lot of space, also it can be regenerated through package.json and package-lock.json(reproducible pieces are not advised to push into git). It contains both direct and transitive 
   dependencies.

Q. What is the `dist` folder?
A. dist contains the production build artifacts generated by the bundler. These files are optimized, bundled, minified, and ready for deployment.

Q. What is transpilation?
A. Transpilation (short for "source-to-source compilation") is the process of converting human-readable source code from one high-level programming language into another high-level 
   language. Unlike traditional compiling, which turns code into machine-readable binary (0s and 1s), transpiling keeps the code in a human-readable, high-level format.

                This is used for CROSS ENVIRONMENT COMPATIBILTY: Developers write modern code (like ES6+ JavaScript, TypeScript, or JSX), but browsers cannot read these newer syntaxes 
    natively. Transpiling converts this modern code into older, widely supported JavaScript (like ES5).

Q. What is 'type' in script tag?
A. The type attribute gives the language of the script or format of the data. Permissible values for type attribute are:
        1. text/javascript or omitted
        - Interpreted as classic Javascript script.
        - You do not need to include type="text/javascript" in modern HTML5. The browser defaults to JavaScript automatically.

        2. module
        - Instructs the browser to treat the code as an ES (ECMAScript)
        - automaticcaly loads as defer attribute.
        - allows to have imports/exports at top of script.
        
        3. importmap

        4. speculationrules

        5. text/template or application/json
        - If the browser does not recognize the value as a scripting language, it completely ignores the script and will not execute it. This is highly useful for 
        embedding data directly inside HTML that your application's JavaScript can read later using the DOM
